# StaySphere CMS

Самостоятельный проект **Guest + CMS**, выделенный из StaySphere. Исходный
`../staysphere` не является зависимостью и не должен изменяться при работе здесь.

## Состав

| Приложение | Назначение | Локальный адрес |
| --- | --- | --- |
| `apps/cms` | Кабинет сотрудников, контент и публичный API | `http://localhost:3101/admin` |
| `apps/guest` | Публичная витрина отеля | `http://localhost:3100` |
| `apps/site` | Product Site с описанием Guest + CMS | `http://localhost:5273` |

Порты отличаются от исходного StaySphere, поэтому проекты могут работать
одновременно. Между ними нет символических ссылок, общих баз или каталогов uploads.

## Запуск

Требуется Node.js 22.13 или новее. В корне этой папки:

```bash
npm ci
npm run dev
```

Приложения также запускаются отдельно: `npm run dev:cms`, `npm run dev:guest`,
`npm run dev:site`. Guest требует доступную CMS.

Вход в локальную CMS: `/admin/sign-in`, пароль `staysphere`.
Локальные изменения каталога и загруженные медиа сохраняются внутри
`apps/cms/.wrangler/`; Guest собственной базы и хранилища не имеет.

## Что входит в CMS

- Данные отеля, логотип, фотографии, удобства и политики.
- Категории и конкретные номера, характеристики и индивидуальные галереи.
- Загрузка фотографий и готовых панорам, обложки и порядок медиа.
- Загрузка готовой последовательности кадров облёта здания, стартовый кадр и
  ключевые ракурсы.
- Редактор зон на кадрах с привязкой к номеру, категории, этажу или ссылке.
- Каталог услуг и питания с описаниями, изображениями и справочными ценами.
- Показ и скрытие номеров, предварительный просмотр в Guest.
- Необязательные справочные цены номеров. Для публикации цена не обязательна.
- Вход сотрудников: администратор и редактор. Редактор управляет контентом,
  администратор также настраивает внешний URL бронирования.

Оболочка кабинета использует исходные сайдбар, карточку отеля, анимированный
активный пункт, мобильное меню и меню пользователя. Светлая, тёмная и системная
темы доступны в сайдбаре; язык кабинета (EN/DE/RU) — в «Аккаунте».
Язык отдельной CMS хранится независимо от основного StaySphere.

В локальной базе сохранена разметка всех ключевых ракурсов: 25 (29 зон),
55 (40), 95 (24), 140 (48). Контуры и привязки также сохранены в
`apps/cms/data/asteria-keyframe-markup.json`. Исходные 48 зон кадра 140
перенесены без изменения геометрии и привязок.

В проекте один отель на развёртывание: исходные демонстрационные данные Asteria
Cove можно редактировать в CMS. Создание нескольких отелей, self-service
регистрация, подписки и биллинг в этот вариант не входят.

CMS принимает готовые материалы; создание облёта и съёмка панорам остаются вне
приложения. Существующий интерфейс захвата/сканирования комнат сохранён; optional
распознавание фотографий использует отдельно настроенный `OPENAI_API_KEY`.
Без ключа карточка заполняется вручную.

## Guest

Интерфейс исходного Guest: главная с облётом, зонами и фотогалереей отеля,
горизонтальные подборки номеров, исходные шапка, меню и подвал, светлая/тёмная
тема и языки. Каталог сохраняет фильтры, сетку, список и интерактивный план
этажей. Страница номера сохраняет галерею, панорамы, удобства, политики,
услуги и питание, боковую сводку и мобильную панель.
Поиск помощника работает по ключевым словам каталога без внешнего AI-сервиса.
Даты и гости нужны для подбора по вместимости и справочного расчёта стоимости;
они не проверяют наличие. Разметка CMS открывает выбранный конкретный номер,
включая его индивидуальные медиа, если они заполнены.
Данные читаются из `GET /api/public/catalog` CMS без кеширования; файлы
`/media/*` проксируются из CMS, исходная фотография скопирована локально.

Внутреннего checkout нет. В `/admin/settings` администратор может задать
HTTP(S)-ссылку на существующий booking engine отеля. Тогда Guest показывает
кнопку перехода; без ссылки кнопки бронирования нет. Справочная цена не является
подтверждением доступности и окончательной стоимости.

## Что не перенесено из PMS

Бронирования, календарь доступности, заселение и переселения, guest CRM и документы,
платежи, бухгалтерия, housekeeping, технические задачи, исполнение заказов,
переписка, email-автоматизации, channel manager и управление тарифами по датам.
В CMS нет этих маршрутов, сервисов и таблиц. Некоторые типы и словари исходного
дизайна сохранены для совместимости общих UI-компонентов.

## Product Site

Визуальная система и композиция скопированы из исходного Product Site.
Тексты и демоссылки описывают Guest + CMS. Старый калькулятор стоимости PMS заменён
запросом предложения; стоимость новой CMS-версии не назначена.
Форма запроса по-прежнему открывает почтовый клиент пользователя и не отправляет
сообщение автоматически.

В `public/ui` сохранены реальные снимки исходного StaySphere, преимущественно
каталога, галерей и 360°. Они не пересняты после выделения CMS и могут отличаться
от обновлённого Guest. Новых макетов вместо скриншотов не создавалось.

## Конфигурация

Примеры находятся в `apps/cms/.env.example`, `apps/guest/.env.example` и
`apps/site/.env.example`. Секреты исходного проекта и его `.env`/`.dev.vars`,
аккаунты, локальные базы, облачные project IDs и привязки ресурсов не перенесены.

Для локальной CMS при необходимости создайте свой `apps/cms/.dev.vars` по примеру.
`ADMIN_PASSWORD` задаёт пароль администратора, необязательный `EDITOR_PASSWORD` —
отдельный пароль редактора. `ADMIN_SESSION_SECRET` подписывает восьмичасовую сессию.
Это два уровня общего доступа по паролю, а не индивидуальные учётные записи команды.

Guest использует `CMS_API_URL`; CMS использует `GUEST_APP_URL` для предпросмотра.
Product Site использует `VITE_CMS_URL` и `VITE_GUEST_URL`.
Локальные значения уже заданы в конфигурации.

Проект не опубликован. Для будущего развёртывания потребуются собственные D1/R2
ресурсы CMS и реальные адреса приложений. В `vite.config.ts` указаны только
изолированные локальные привязки; существующие облачные ресурсы StaySphere не
используются. В production обязательны собственные пароль администратора и
секрет сессии длиной от 32 символов.

## Проверка

Тесты, сборка, линтер, typecheck и браузер при выделении не запускались — по
рабочему соглашению это следующий этап по запросу пользователя.
Зависимости установлены, приложения запущены на портах выше. Редактор разметки:
`http://localhost:3101/admin/content/spinner/markup` (также в меню CMS).
Для ручной проверки: измените номер в CMS, откройте его в Guest, проверьте галерею,
панораму, привязку 360°-зоны и переход во внешний booking engine.

Доступные команды для последующей проверки: `npm run build:cms`,
`npm run build:guest`, `npm run build:site`, `npm run typecheck:cms`,
`npm run typecheck:guest`, `npm run lint:cms`, `npm run lint:guest`,
`npm run lint:site`.
